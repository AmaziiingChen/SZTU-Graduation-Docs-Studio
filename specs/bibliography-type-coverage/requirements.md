# 参考文献类型覆盖要求

## 范围

增强开题报告和任务书共用的本地 BibTeX 导入器，使学校示例中出现的书籍、标准、
会议文献和网络资源能够生成稳定、可检查的参考文献段落。深圳技术大学当届官方材料
优先于通用国家标准；本次不实现正文引文样式或毕业论文参考文献管理器。

## 用户故事与验收条件

### R1 书籍与书籍章节

- 当用户导入 `@book` 时，系统应保留作者或编者、书名、版次、出版地、出版社、年份和页码。
- 当用户导入 `@inbook` 或 `@incollection` 时，系统应将其作为书籍析出文献生成 `[M]//`，
  不得误标为会议论文 `[C]//`。

### R2 会议文献与标准

- 当用户导入 `@inproceedings` 或 `@conference` 时，系统应生成会议析出文献 `[C]//`。
- 当用户导入 `@proceedings` 时，系统应生成会议录 `[C]`。
- 当用户导入 `@standard` 时，系统应生成标准 `[S]`，并保留发布机构和标准编号。

### R3 网络资源

- 当用户导入 `@online`、`@electronic` 或 `@www` 时，系统应生成 `[EB/OL]`，并保留 URL
  和引用日期。
- 当 `@misc` 具有 URL 时，系统应按网络资源处理；没有 URL 时应使用其他文献标识 `[Z]`，
  不得把所有 `@misc` 静默标成网络资源。

### R4 前后端一致与兼容

- 当桌面端认定 BibTeX 有效时，后端导出信任边界应接受同一组条目类型。
- 现有期刊、学位论文、报告、专利、书籍和旧草稿应继续可读。
- 原始 BibTeX 不得进入渲染输入、遥测或错误详情。

### R5 回归验证

- 每种新增或修正的类型都应有确定性的格式化测试。
- 后端应测试新增类型、重复键、缺少必填字段和不支持类型。
- 任务书仍接收每条独立的结构化参考文献段落，不改变模板版式。
