# ADR 0005：开发模板工程实时同步为内容寻址快照

- 状态：Accepted
- 日期：2026-08-30
- 决策者：项目维护者

## 背景

开题报告、任务书、中期检查和毕业论文模板会与桌面工作台并行开发。若工作台只接受某次提交的固定哈希，模板工程每次修改都会导致开发导出失败；若直接执行正在修改的 Python、Word 或 LaTeX 文件，又可能在一次导出中混入前后两个状态，也无法准确记录使用的模板版本。

## 决策

开发态支持显式关联本地模板工程，并可发现相邻的受控模板检出。每次环境检查、导出预检和正式导出都重新读取文档类型允许清单内的文件，拒绝绝对路径逃逸和任意层级符号链接，计算规范化组合 SHA-256，再通过临时目录和原子重命名写入应用私有目录中的内容寻址快照。

渲染器只执行快照，不直接执行可变源目录。快照版本采用 `<合同版本>+workspace.<指纹前缀>`，完整指纹写入预检令牌、导出任务、回执和安装记录。源文件在预检后变化会生成另一快照，使旧预检令牌失效并要求重新预检。旧快照保留，不被覆盖。

开发工作区信任来自用户显式选择或开发检出的受控相邻路径，只用于本地开发，不代表模板已验收、已提交或可再分发。正式模板继续使用固定版本、固定逐文件哈希、来源和许可证门禁；动态工作区不能替代发布模板包。

## 后果

- 模板工程修改无需反复更新硬编码哈希或覆盖安装目录；
- 每次导出仍对应一个不可变、可复核的模板指纹；
- 开发来源与正式可信版本在状态和文案上保持明确区分；
- 内容快照会累积，后续清理必须按精确快照列举并单独设计，不得用通配符或 Git 忽略状态删除。

## 验证

单元测试覆盖首次关联、同指纹幂等、源文件变化生成新快照、旧快照不变、开题报告与中期检查共用流程、符号链接拒绝和正式固定哈希漂移拒绝。前端测试覆盖当前文档模板不可用时禁用导出。真实开发验收使用当前 `/Users/chen/Thesis` 工作树完成预检和导出，并核对回执中的工作区模板指纹。
