# ADR 0009：文档板块导航始终可见

- 状态：Accepted
- 日期：2026-09-01
- 决策者：项目维护者
- 替代：ADR 0002 和 ADR 0007 中“窄窗口使用紧凑文档板块 `Select`”的部分

## 背景

文档板块导航承担选题意义、研究内容、研究方法、研究步骤和参考文献等写作区域之间的
直接跳转。此前窗口宽度小于 1200 px 时，工作台会主动删除这一列并替换为顶部
`Select`。该变化使导航位置和操作方式随窗口宽度改变，也容易被理解为板块导航已经
消失。

最左侧应用 Sidebar 已经提供官方 `offcanvas` 折叠机制，可以在空间不足时释放主要
编辑宽度。文档板块导航没有必要再建立第二套折叠行为。

## 决策

文档板块导航固定为 `12rem`，在所有 Electron 支持的窗口宽度下保持可见、不可折叠、
不可隐藏、不可拖拽调宽，并继续使用同一组可访问按钮切换板块。

窗口空间不足时，只允许最左侧应用 Sidebar 通过现有 `SidebarTrigger` 折叠。工作台不再
监听 1200 px 断点，不再渲染文档板块 `Select`，正文编辑区继续通过 `min-width: 0`
承担剩余空间。

## 后果

- 用户在任意支持的窗口宽度下都能直接看到并跳转文档板块；
- 文档板块列从 `14rem` 缩小到 `12rem`，为正文释放 32 px；
- 只有最左侧应用 Sidebar 具有折叠语义，两个导航层级不再互相混淆；
- 极窄移动网页不再是独立布局目标，Electron 的 `1100 px` 最小窗口宽度是当前验收边界。

## 验证

组件测试在 `1100 px` 窗口宽度下折叠应用 Sidebar，并断言文档板块导航仍存在、宽度为
`12rem`、不存在“选择文档板块”组合框，且板块按钮仍可操作。人工复核同时检查默认
窗口和最小窗口宽度下的正文剩余空间与导航文字完整性。
