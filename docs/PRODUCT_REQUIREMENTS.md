> PRD（Product Requirements Document，产品需求文档）
> 状态：草案（按「一次性工具」定位修订），待评审
> 日期：2026-11-26
> 范围：Windows 桌面版下一版发布的产品化补强（不含代码签名/证书）

## 0. 一句话定位

**这是一个「用完即走」的一次性工具**：一个学生在本机上生成自己那一份任务书、一份开题报告、一份中期检查、几份评审表，导出、交掉，结束。

它不是文档管理系统，也不是长期写作平台。用户不会在这里管理几十份文档、跨设备同步、回看历史版本或批量处理；这些能力不做，也不该做。

由此推导出的取舍：

- 做：让第一次打开的人知道怎么用；让填写和导出一次成功；失败时看得懂、能恢复继续；有通知能触达；有反馈能找到我们。
- 不做：版本历史、自动备份、项目包迁移、打印、批量导出、无障碍专项、多文档管理、云同步。

## 1. 背景

### 1.1 产品是什么

SZTU 文档工作台（SZTU Docs Studio）面向深圳技术大学新材料与新能源学院的学生，覆盖七类材料：

1. 任务书
2. 开题报告
3. 中期检查
4. 指导教师评审表
5. 评阅人评审表
6. 答辩记录表
7. 成绩考核表

另有毕业论文：本软件**不编辑论文正文**，只提供 LaTeX 模板下载与字体、引擎支持。

用户在本机填写内容，软件负责版式、字体、图表编号、参考文献著录，最终导出可提交的 PDF 或 Word（Word 供继续修改，PDF 为最终版式）。

### 1.2 现在的位置

功能层面已经可用：七类材料可填写、预览、导出；安装包内置 TeX 引擎、PDF 工具与全部模板字体；错误提示已改成人话；自动更新支持下载后一键安装并重启（本地已实现，未发布）。

但从「成熟对外发布」的标准看，缺的是**第一次就能用顺、出问题能自救、我们够得着用户**：

- 用户不知道从哪开始（帮助只在外部网页里）。
- 出故障时只能创建诊断包发给我们，应用内没有反馈入口，崩溃会直接白屏。
- 云端公告只有一个纯文本弹窗 + 一个链接，发不了图、多个链接，也进不到应用内页面。
- 没有应用内「关于 / 隐私 / 许可」页面。

### 1.3 本轮目标

补齐「可学习、可支持、可触达、可度量」，让一个没有技术背景的学生在干净 Windows 上**第一次就能走通**，出问题时**知道下一步做什么**。

**明确不做（本轮及可预见版本）**：

- 版本历史、修订回退；
- 自动备份、项目包导出/导入、换机迁移；
- 打印、批量导出、多文档队列；
- 无障碍专项（键盘与读屏优化）；
- 云同步、多设备协作、文档管理（标签/搜索/归档）；
- 论文正文编辑器（永久不做）；
- 代码签名、公证、SmartScreen 信誉（另行处理）；
- macOS 正式版、模板市场、AI 写作。

> 判断标准：一个学生一辈子只写一次的东西，不需要「管理」；需要的是一次做对。

## 2. 用户与场景

### 2.1 用户角色

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 学生（主要） | 大四本科生，写任务书、开题、中期、评审表 | 少折腾格式，顺利导出，别丢内容 |
| 导师 / 评阅人 | 收 PDF 或 Word 看内容 | 文件能打开、版式正常 |
| 教务老师 | 汇总材料 | 命名统一、格式合规 |
| 维护者（我们） | 发布、答疑、排障 | 能定位问题、能通知用户、能回滚 |

用户特征：普通学生和老师，没有开发经验，不熟悉 LaTeX、字体、环境变量；遇到红色报错会紧张，需要「说人话 + 告诉我下一步点哪」。

### 2.2 关键场景

1. **第一次使用**：安装后不知道从哪开始，希望三步内知道怎么做。
2. **第一次预览失败**：想知道哪里错了、怎么改，而不是看到错误码。
3. **填到一半关掉软件**：再打开内容还在，能继续。
4. **导出前**：确认版式无误，一次成功导出 PDF / Word。
5. **换一台电脑**（少见）：重新安装后能继续，不要求一键迁移。
6. **我们发通知**：用户能看到新版说明、使用技巧、活动通知，并能点链接继续了解。
7. **软件崩溃**：重新打开能继续，而不是白屏。

---

## 3. 产品原则

1. **一次性优先**：为「只做一次」优化，不为「长期管理」增加复杂度。
2. **本地优先**：文档、图片只存本机；上传必须用户主动且知情。
3. **零依赖**：安装后不需要用户装 TeX、字体、Office。
4. **人话优先**：错误提示说清「哪里错、怎么改」，不暴露错误码。
5. **一步可达**：常用动作不超过两次点击；帮助与通知不阻断主流程。
6. **不打扰**：首启不强制弹窗；通知可关；帮助按需打开。

## 4. 现状与差距（基于代码的事实）

| 能力 | 现状 | 差距 |
|---|---|---|
| 消息/公告 | 签名清单里一条纯文本公告 + `help_url` 单按钮（`apps/desktop/src/App.tsx` 公告弹窗） | 无消息中心、无图、无多链接、无应用内跳转、无定向、无已读 |

## 5. 本轮范围（P0）

### 5.1 应用内消息中心

#### 目标

把「公告」升级为「消息中心」：能发一条或多条、带图、带多个链接、能跳应用内页面、能按版本/平台定向、有已读与历史。

#### 用户故事

- 作为学生，我在侧边栏看到未读红点，点开能看使用技巧，并直接跳到「使用指南」页面。
- 作为老版本用户，我能收到「请手动下载新版」的消息，并点到下载页。
- 作为维护者，我能发一条只对 0.1.13–0.1.15 生效的消息，不影响新版本用户。

#### 功能需求

**FR-1 消息模型**

每条消息包含：

- `id`：稳定标识，用于已读状态。
- `title`、`summary`：列表与详情标题。
- `body`：内容块数组，支持 `paragraph`、`image`、`button`、`divider`、`link`。
- `severity`：`info` / `important` / `critical`。
- `starts_at` / `ends_at`：生效窗口。
- `dismissible`：是否可关闭；`critical` 强制不可关闭。
- `audience`：`min_version`、`max_version`、`platform`、`arch`（全部可选）。
- `actions`：0–3 个按钮，类型为：
  - `external`：HTTPS 外链，系统浏览器打开；
  - `in_app`：应用内路由，只允许白名单页面（使用指南、常见问题、更新说明、设置）；
  - `download`：指向安装包或资料下载。
- `image`：可选 HTTPS 图片，限制 1 张、≤2 MB、png/jpg/webp。

**FR-2 投递与签名**

- 新清单地址 `releases/v2/stable/manifest.json`（schema 3.0），旧地址继续冻结为 schema 2.0，供 0.1.13–0.1.19 使用。
- 发布脚本对两份清单分别签名（同一把私钥），CI 用「冻结的旧解析器」校验旧清单仍合法。
- 客户端每 30 分钟拉取新清单；失败沿用上次结果，不影响编辑。

**FR-3 界面**

- 侧边栏新增「消息」入口，未读红点（数字 ≤9，超过显示 9+）。
- 消息列表：标题、时间、级别标签、未读圆点；按时间倒序。
- 消息详情：内容块渲染；按钮按 `actions` 显示；底部「我知道了」。
- `critical`：不可关闭，阻塞进入工作台，只给「查看详情 / 退出应用」。
- 已读状态存本机（消息 id + 版本），跨重启保留；提供「全部标为已读」。
- 历史消息分页（最近 50 条）。

**FR-4 应用内路由白名单**

`guide`（使用指南）、`faq`（常见问题）、`release-notes`（更新说明）、`settings`（设置）。

路由必须以枚举校验，禁止任意 URL 或脚本。

#### 验收标准

1. 一条消息带 2 个按钮（1 个外链、1 个应用内页面），点击行为正确。
2. 只对 `min_version=0.1.13`、`max_version=0.1.15` 的消息，在 0.2.0 客户端不可见。
3. 已读后红点消失，重启后仍为已读。
4. `critical` 消息阻塞工作台，重开仍阻塞（直到过期或升级）。
5. 旧版客户端（0.1.13）读取旧清单不受影响（CI 用冻结解析器验证）。
6. 图片加载失败时显示占位，不影响正文。

#### 埋点

`message_impression`、`message_click`（action 类型/目标）、`message_dismiss`、`messages_opened`。

### 5.2 帮助中心 + 演示模式

#### 目标

让用户在应用内学会使用，不依赖外部网页；演示资料可随时载入/清除。

#### 功能需求

**FR-5 帮助中心**

- 侧边栏「帮助」入口（与消息中心并列）。
- 页面结构：搜索框、分类（安装与更新 / 填写与编辑 / 文献 / 预览与导出 / 疑难排查）、文章详情。
- 内容本地内置，随版本更新；断网可用。
- 搜索：标题 + 正文关键词，返回高亮片段。
- 上下文帮助：表单字段旁「?」，点击打开对应文章锚点。
- 快捷键面板：`Ctrl+/` 打开「键盘快捷键」。
- 更新说明页：内置最近 3 个版本的变更摘要。

**FR-6 演示模式**

- 帮助页与空工作区提供「载入演示资料」「清除演示资料」。
- 演示资料：任务书、开题报告、中期检查三份，标题统一前缀「参考样例·」，内容为虚构人物。
- 只追加缺失文档，不覆盖用户已有文档；清除只删前缀匹配文档。
- **不自动种入**：首启、打开工作区都不自动创建。
- 演示资料写入活动档案；没有档案时创建演示档案并设为活动。

#### 验收标准

1. 搜索「文献 空值」能命中对应文章。
2. 字段「论文题目」旁「?」打开帮助并定位到「档案」章节。
3. 载入后侧边栏出现三份文档并自动展开分类；再次点击提示「已存在」。
4. 清除后三份文档消失，用户自己的文档不受影响。
5. 全新安装、首次启动不会自动创建任何演示文档。
6. 断网时帮助仍可用。

### 5.3 崩溃兜底 + 应用内反馈 + 诊断增强

#### 目标

任何崩溃都不再白屏；用户能找到我们，我们能拿到编号。

#### 功能需求

**FR-7 错误边界**

- 根级 + 每个主面板级 Error Boundary。
- 兜底界面：「界面出错了」+「重新加载界面」「创建诊断包」。
- 记录最近一次崩溃时间与堆栈（本机，脱敏，最多 5 份）。
- 连续 2 次启动后 5 分钟内崩溃 → 启动时提示进入安全模式（禁用自动预览、自动更新检查）。

**FR-8 主进程崩溃处理**

- `uncaughtException` / `unhandledRejection` 记录本地崩溃日志；避免循环重启。
- 崩溃日志进入诊断包，不自动上传。

**FR-9 应用内反馈**

- 「帮助 → 反馈」表单：类型（问题/建议/内容错误）、描述（≤1000 字）、可选附诊断编号、可选留联系方式。
- 提交到云端接口，带速率限制与 schema 校验；返回回执编号。
- 明确文案：不会自动附带正文；诊断包需另行点击发送。

**FR-10 诊断包增强**

- 发送前显示文件清单（文件名、大小）与「包含正文/路径」警示。
- 提供「复制诊断编号」按钮。
- 本地诊断保留 48 小时（现状），云端 30 天（现状）。

#### 验收标准

1. 人为让某个面板抛错，只有该面板显示兜底，其他功能可用。
2. 根级崩溃后能「重新加载界面」并恢复工作区。
3. 反馈提交成功返回回执；断网时提示稍后再试，不丢草稿。
4. 诊断包发送前能看到文件清单。

### 5.4 关于 / 隐私 / 许可（支撑页面）

- 「关于」：版本、构建时间、引擎版本、模板版本、更新通道。
- 「隐私」：遥测采集范围、诊断包内容、保留期限、如何删除。
- 「开源许可」：第三方依赖清单与许可证。
- 「检查更新」「查看更新日志」「导出诊断包」入口。

### 5.5 新人交互引导（首次使用）

#### 目标

首次打开软件时，用**可交互的分步指引**带用户完成一遍真实操作（填档案 → 建任务书 → 写正文 → 预览导出），而不是读一段纯文字。用户必须真的点到高亮元素才进入下一步。

#### 功能需求

**FR-11 触发条件**

- 仅在「全新用户」首次打开时自动出现：工作区没有任何档案、也没有任何文档，且本机未完成过引导。
- 已完成标记存 `localStorage`（`sztu-docs.first-run-tour-v1`）；用户跳过也算完成，不反复打扰。
- 已有档案或文档的用户不自动出现；后续在「帮助」里提供「重新查看新手引导」。

**FR-12 步骤与交互**

- 半透明遮罩 + 高亮目标元素（挖孔/描边），目标旁浮动说明卡片（标题、一句话说明、步骤序号「第 N 步 / 共 5 步」）。
- 需要点击的步骤：卡片提示「请点击高亮的按钮」，用户真的点击目标后才前进；提供「跳过引导」。
- 不需要点击的步骤（如填档案页）：显示「下一步」按钮。
- 目标元素不存在时（例如窗口太窄未渲染）自动跳过该步，不卡住。
- 步骤：

| 步 | 目标 | 要求 | 文案要点 |
|---|---|---|---|
| 1 | 侧边栏「档案与基本信息」 | 点击进入 | 先花一分钟把姓名、学号、学院、专业、导师填一次，之后所有材料自动带出 |
| 2 | 档案表单 | 「下一步」 | 论文题目也可以在这里改；学号按学校格式填 |
| 3 | 侧边栏「任务书」右侧加号 | 点击新建 | 点加号新建一份任务书 |
| 4 | 编辑区右侧结构提示 | 「下一步」 | 按提示逐项填写，保存自动进行，不用找保存按钮 |
| 5 | 右上角「预览&导出」 | 点击打开 | 先看分页效果，再导出 PDF（推荐）或 Word |
| 收尾 | 无 | 「完成」 | 就这三步：填资料、写正文、导出；遇到问题点左下角「帮助」 |

- 引导过程中不阻断键盘输入；`Esc` 等同「跳过」。
- 引导结束后焦点回到主编辑区，不留下遮罩。

**FR-13 与帮助中心的衔接**

- 引导完成后，帮助中心首页显示「三步上手」卡片，可再次进入引导。
- 帮助页提供「重新播放新手引导」按钮。

#### 验收标准

1. 全新安装（无档案、无文档）首次启动，自动出现第 1 步，高亮侧边栏「档案与基本信息」。
2. 不点击目标时无法进入第 2 步；点击后自动前进。
3. 点击任务书加号后确实创建文档，引导进入第 4 步。
4. 点击「预览&导出」后引导进入收尾；点「完成」后遮罩消失。
5. 完成后重启应用不再自动出现；「帮助 → 重新播放新手引导」可再次出现。
6. 已有档案或文档的用户首次打开不会自动出现。
7. 窗口缩小导致目标不可见时，该步骤自动跳过，不出现空白遮罩卡死。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 启动到可操作 ≤3 s（本机中等配置）；消息中心打开 ≤300 ms；帮助搜索 ≤200 ms |
| 可靠性 | 草稿自动保存；任何写操作先写临时文件再原子替换；崩溃后重启可恢复 |
| 兼容 | Windows 10 1909+ / Windows 11；100%–200% 缩放；中文用户名与中文安装目录；无 Office 环境可完成 PDF 导出 |
| 易用 | 关键路径（填档案→填文档→预览→导出）无需阅读文档即可完成；按钮文字用动作描述 |
| 安全 | 消息/更新清单严格 schema + Ed25519 验签；应用内路由白名单；反馈接口限流 |
| 隐私 | 遥测不含正文/路径/姓名学号；诊断包上传需二次确认并展示清单；保留期限明确 |
| 可维护 | 新能力均有单测；消息、反馈、诊断路径有集成测试 |

## 7. 度量

## 8. 发布计划

1. 内部可用版本 → 团队自测（消息、帮助、崩溃兜底）。
2. 邀请 10–20 名用户（含 0.1.13–0.1.15 老版本用户）灰度。
3. 全量发布：先部署云端（清单 3.0 / 消息 / 反馈接口 / 帮助内容），再发客户端。
4. 回滚：保留上一版安装包与旧清单；消息可下线。
5. 发布检查清单：
   - 干净 Windows（无 Office/TeX/字体）安装、导出；
   - 中文安装目录、中文用户名、非管理员；
   - 0.1.19 → 新版一键更新；
   - 消息定向、富内容、应用内跳转；
   - 崩溃兜底演练；
   - 反馈提交通路。

## 10. 风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| 清单 3.0 与旧客户端不兼容 | 老用户收不到消息 | 双清单双签 + 冻结旧解析器 CI 校验 |
| 图片/外链被滥用 | 安全与合规 | 仅 HTTPS、大小限制、内容审核、路由白名单 |
| 错误边界掩盖真实 bug | 问题被吞 | 兜底界面提供诊断包 + 崩溃日志（经同意上传） |
| 反馈接口被刷 | 垃圾数据 | 限流、schema 校验、人工审核 |
| 帮助内容与功能不同步 | 误导用户 | 帮助随版本内置，发布检查单校验 |

**依赖**：

- 云端：CloudBase 静态托管（清单、帮助内容、图片）、函数（反馈接口）。
- 发布：Ed25519 私钥、签名脚本、CI 打包与验收。
- 内容：帮助文章、更新日志、消息文案、隐私说明。

## 11. 已定决策

1. 消息图片：放 CloudBase 外链（HTTPS、大小与格式校验）。
2. 反馈：**必须**留联系方式（邮箱或手机号），便于回访。
3. 帮助内容：做远程可更新的帮助中心，本地缓存兜底。
4. 演示资料：随安装包内置（不联网即可载入）。
5. 新人引导：做交互式分步引导，必须真实点击才前进（见 5.5）。
