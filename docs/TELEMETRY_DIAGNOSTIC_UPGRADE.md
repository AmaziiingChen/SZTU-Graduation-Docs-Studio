# 学院专业统计与诊断升级

范围：本地源码升级，不打包、不部署。先执行 `20261006090000_accept_diagnostic_reports.sql` 扩展数据库版本约束，再部署包含 diagnostic-context.cjs 的完整云端接收目录，最后发布客户端。接收端兼容旧客户端；新客户端重新确认 1.2 隐私说明后才能发送。

学院、专业从已保存或已载入档案读取，保留目录外的手填名称，仅去除首尾空白；沿用档案字段的 200 字符上限，未填写才记为 unknown。不猜测简称、不强行归类。不会读取并附带姓名、学号、班级和正文等其他字段。管理页按查询区间每个安装标识按事件发生时间选取最后一条记录计数（旧记录缺失发生时间时使用接收时间）；标识每 30 天轮换，不能解释为学生人数。沿用既有 Table/Card 和主题，不新增组件。

诊断使用显式字段和枚举，保持主动创建、预览、发送。新增毫秒耗时与请求关联标识、结构摘要和受限调用位置；不收集正文、异常原文、绝对路径、局部变量。旧诊断仍可读取。

℃ 校验以模板兼容字符规则为准，保留上标、下标和字形样式校验。测试验证隐私边界、协议兼容、分布去重和科学符号回归。界面构建不能代替目标编辑器验收。

## 诊断格式 3.0

每次操作的各环节用随机请求编号关联。报告包含文档类型、阶段、毫秒耗时、结果及稳定错误码。外部工具可额外提供工具名、来源、版本、退出码和预定义原因。环境探测、工作区与数据库、档案与草稿、模板解析、输入检查、PDF 编译与字形检查、预览转图、Word 生成与结构检查、导出写入、更新校验、诊断上传与回执都有阶段记录。报告按需生成，正文、档案字段值、绝对路径和工具原始输出不进入报告。

从挂载的 macOS 安装镜像取出应用路径，运行 `node scripts/accept_macos_diagnostics.mjs "<应用路径>" --profiles` 可重复打包产物验收。脚本使用临时工作区和合成数据。诊断请求经过实际接收端的 HTTP 处理、报告校验和回执逻辑，保存及读回由本机内存模拟。多档案测试通过安装包内的工作区与渲染进程生成并导出两份任务书，逐份校验姓名、学号、题目和正文归属。

腾讯云验收使用独立测试环境，先应用 `20261113090000_accept_diagnostic_steps.sql`，再部署接收端。以测试客户端回执的 `report_id` 查询测试库中的 `diagnostic_reports`，核对阶段、工具、退出码和脱敏字段。旧客户端的 1.0 和 2.0 报告仍在接受范围内。

## 完整故障包

故障材料随本次失败保存在本机。覆盖环境与文档检查、预览、导出预检与执行、打开工作区、新建文档、保存档案和草稿、安装模板。「创建诊断包」打开完整包的确认窗口，优先使用关联故障或最近的可用故障；本机没有可用故障材料时，采集当前运行环境和已保存的文档现场。界面列出文件、大小和遗漏材料，只有用户确认「发送诊断包」后才发出网络请求。旧版客户端的报告继续使用原有格式和接收路径。

包内记录实际请求、文档与档案快照、实际渲染输入、所引用的受管素材、可信模板文件、原始子进程输出、异常堆栈、步骤记录及仍能读取的临时产物。进程崩溃时可恢复已写出的材料。文档引擎标准错误按请求写入本机，能明确归属的启动错误最多保留 256 KiB，无法明确归属的异常协议片段会标注为缺失。旧模板内部丢弃的输出无法恢复。应用源码用版本和冻结引擎的 SHA-256 校验值定位，使用的模板源码随包保留。本机最多保留最近 5 份失败包，每份最长 48 小时。大于 8 MiB 的包可完整保存到本机。云端包在入库后保留 30 天。

部署顺序为应用 `20261113091500_create_full_diagnostic_reports.sql`，部署接收服务，再连通 `/v1/full-reports` 路由。接收端存储原始 ZIP 字节，写入后按报告编号回读校验值并返回回执。维护者使用有授权的数据库工具按编号读取 `public.full_diagnostic_reports` 的 `archive_base64`，解码后校验 `sha256`。接收服务只存档，不解包。检查本机、云端路由和真实入库应分别验证。
